# 第 11 章 构建与打包

本章使用问候与本地便笺工程，练习正式构建、单独运行和生成 Windows 安装包。版本基线为 Wails CLI v3.0.0，模板为 `vanilla-js`，模块路径为 `example.com/learn/first-wails`。

本章目录中的 `project/first-wails` 是完整工程。先完成第 2 章的工具准备，再在本章目录进入工程。

```powershell
Set-Location .\project\first-wails
Get-Location
Get-ChildItem
```

确认当前目录中有 `go.mod`、`Taskfile.yml`、`main.go` 和 `frontend`。

## 1. 开发、构建和打包

| 任务 | 命令 | 结果与用途 |
| --- | --- | --- |
| 开发调试 | `wails3 dev` | 启动开发流程，观察源码修改 |
| 正式构建 | `wails3 build` | 在 `bin` 中生成当前平台程序 |
| 分发打包 | `wails3 package GOOS=windows` | 执行 Windows 分发任务，默认生成 NSIS 安装包 |

Wails 通过项目中的 Taskfile 组织构建。学习本项目时，可以同时查看根目录、`build/Taskfile.yml` 和 `build/windows/Taskfile.yml` 中的任务。[构建应用](https://v3.wails.io/guides/build/building/)

## 2. 构建 Windows EXE

若开发命令正在运行，先回到原终端按 `Ctrl+C`。在项目根目录执行。

```powershell
wails3 build
Get-ChildItem .\bin
```

本项目的 Windows 输出为 `bin/first-wails.exe`。任务生成调用绑定、构建前端，再编译 Go。`main.go` 中的嵌入指令将前端构建资源交给正式程序。

```go
//go:embed all:frontend/dist
var assets embed.FS
```

打包前端与生成绑定的具体依赖关系可在本工程的 `build/Taskfile.yml` 中查看。任务显示已经是最新状态时，可以复用已有结果。构建失败时，保留第一条具体错误，按第 10 章的方法处理。[Go embed 文档](https://pkg.go.dev/embed)

## 3. 单独运行构建产物

在项目根目录执行。

```powershell
.\bin\first-wails.exe
```

也可以把 EXE 复制到自己新建的独立目录，通过资源管理器双击打开。本章制作时，将 EXE 放到单独目录，在该目录启动并完成问候、便笺保存与重启检查。

| 操作 | 预期结果 |
| --- | --- |
| 输入 `小明` 并点击问候 | 显示 Go 返回的中文问候 |
| 输入中文、多行文字后保存 | 显示保存成功 |
| 关闭并重新打开正式程序 | 读取最后保存的内容 |
| 清空、保存并重启 | 编辑区为空，读取成功 |

便笺通过 `os.UserConfigDir()` 定位到当前用户配置目录下的 `WailsLearningNote/note.txt`，页面底部显示实际位置。核对旧内容时，检查保存结果与该路径。[UserConfigDir 文档](https://pkg.go.dev/os#UserConfigDir)

## 4. 准备 NSIS

Windows 默认打包流程使用 NSIS。官方提供的 Windows 安装入口如下，安装完成后重新打开终端，检查编译器。

```powershell
winget install NSIS.NSIS
Get-Command makensis
makensis /VERSION
```

也可以从 NSIS 官方页面取得压缩包，解压后将包含编译器的目录加入当前进程或用户的 `Path`。本次使用官方 NSIS 3.13 压缩包，并对照官方发布数据核验 SHA-256。[Wails Windows 打包指南](https://v3.wails.io/guides/build/windows/)、[NSIS 下载](https://nsis.sourceforge.io/Download)、[NSIS 官方发布数据](https://github.com/NSIS-Dev/release-data)

## 5. 准备课堂产品信息

本章工程的 `build/config.yml` 使用专门的课堂产品名与版本。

```yaml
info:
  companyName: "WailsLearning"
  productName: "Wails Chapter 11 Note"
  productIdentifier: "com.wailslearning.chapter11note"
  version: "1.0.0"
```

更新配置后，在项目根目录执行。

```powershell
wails3 task common:update:build-assets
```

该任务重新生成平台构建资源。已有定制安装脚本、图标或平台配置时，先查看将被更新的文件与具体差异，再运行任务。本章已运行该任务，安装向导显示对应的课堂产品名。Windows 文件信息可以在 `build/windows/info.json` 中查看，NSIS 脚本位于 `build/windows/nsis`。

## 6. 生成安装包

Windows 默认命令如下。

```powershell
wails3 package GOOS=windows
```

本项目的 Windows Taskfile 支持 `INSTALL_SCOPE`。本章实际构建使用当前用户安装范围。

```powershell
wails3 package GOOS=windows INSTALL_SCOPE=user
```

该参数由本工程的 `build/windows/Taskfile.yml` 转交给 NSIS。模板默认值为 `machine`，设置为 `user` 时使用当前用户的程序目录。以配套任务文件中的定义为准。

本次生成的文件如下，大小为本次构建记录。

| 文件 | 本次大小 | 用途 |
| --- | --- | --- |
| `bin/first-wails.exe` | 11,185,152 字节 | 直接启动便笺 |
| `bin/first-wails-amd64-installer.exe` | 6,561,478 字节 | 打开 NSIS 安装向导 |

输出名中的 `amd64` 对应本次 Windows 64 位目标。修改名称、资源、版本或架构后，以实际任务输出为准。[Windows 安装器](https://v3.wails.io/guides/build/windows/)

## 7. 目标机器的 WebView2

目标机器运行应用需要 WebView2 Runtime。默认 NSIS 流程带有引导程序，在需要时下载安装运行时。离线分发需要准备完整的 Evergreen Standalone Installer，并按对应方式测试。[Microsoft WebView2 分发说明](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution)

发布前，在目标电脑或合适的测试环境继续完成以下检查。

- 安装向导中的产品名、版本和目标目录符合预期。
- 安装后可以从预期入口启动。
- WebView2 就绪，页面和 Go 调用正常。
- 中文、多行内容和空文本可以保存与重新读取。
- 卸载结果、快捷方式与数据处理符合产品约定。

## 8. 平台与架构

本章实测目标为 Windows amd64。macOS、Linux 和其他架构各有工具链、系统依赖及分发格式，按目标平台单独准备并验收。[跨平台构建](https://v3.wails.io/guides/build/cross-platform/)
