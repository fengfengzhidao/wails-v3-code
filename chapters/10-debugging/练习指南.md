# 第 10 章练习指南 · 调试和排错

本章按“复现、定位、修复、重复原操作验收”的顺序练习。本章目录包含健康便笺工程、隔离故障副本，以及制作时的失败与修复日志。

## 1. 先准备一份独立练习副本

建议复制本章目录后完成故障实验。健康便笺工程位于 `project/first-wails`，Go 小练习位于 `labs/go-compile`，绑定与元素 ID 的对照文件位于 `labs` 的对应目录。

启动健康工程。

```powershell
Set-Location .\project\first-wails
wails3 dev
```

本章原生实测使用了另一个可用端口。

```powershell
wails3 dev -port 9246
```

`-port` 指定 Vite 开发端口，实际地址会出现在启动日志中。[开发命令参数](https://v3.wails.io/guides/cli/)

## 2. 先按现象判断层次

| 现象 | 优先检查 |
| --- | --- |
| 命令找不到 | 工具安装位置、PATH、当前终端 |
| Go 编译失败 | 文件、错误行、名称、导入和返回值 |
| 页面或按钮异常 | Console、查找结果、HTML 元素 ID |
| 绑定模块解析失败 | `go.mod`、实际生成目录和导入路径 |
| 保存失败 | Go 返回的文件操作错误与数据路径 |
| 重启读到旧内容 | 本次保存结果与实际读取文件 |

每次只做能够解释当前原因的小修复，再重复原来的操作，核对目标错误和功能结果。

## 3. Go 编译名称错误

在本章目录进入错误副本。

```powershell
Set-Location .\labs\go-compile\broken
go run .
```

制作时实测错误为。

```text
.\main.go:6:9: undefined: fmt.Prinln
```

回到第 6 行，将 `fmt.Prinln` 修正为 `fmt.Println`，再执行 `go run .`。参考答案位于旁边的 `fixed` 目录，预期输出为 `Go 编译已恢复`。

## 4. 元素 ID 错误与 Console

本章在原生开发窗口中，通过右键“检查”打开开发者工具，再选择 Console。

故障副本把 HTML 的按钮写成了以下内容。

```html
<button id="save-buton">保存便笺</button>
```

脚本查找的却是完整标识。

```javascript
const saveButton = document.getElementById("save-button");
console.log("开始绑定保存按钮", saveButton);
```

本机 Console 先显示 `null`，随后在 `src/main.js:39:12` 发生以下目标异常。

```text
Cannot read properties of null (reading 'addEventListener')
```

把 HTML 改为 `id="save-button"`，保存并重新加载。核对查找结果恢复为按钮元素，再实际完成读取、输入与保存。本机已经核对写入的 UTF-8 文件内容。

`labs/dom-id` 保存了完整的错误与健康 HTML 对照。视频原生窗口使用独立数据目录完成测试。

## 5. Go 日志与前端日志

在 Go 文件中导入 `log`，把日志放在具体步骤附近。

```go
log.Println("开始加载便笺")
```

配套工程把它放在实际读取文件之前。前端可记录当前变量值，并在已有的 `catch (error)` 中查看完整错误对象。

```javascript
console.log("开始绑定保存按钮", saveButton);
console.error(error);
```

后一句放在已有错误分支中使用。运行日志与源代码位置共同提供线索。[Wails 调试资料](https://v3.wails.io/guides/dev/debugging/)

## 6. 绑定导入路径不匹配

先确认项目根目录 `go.mod` 中的模块名，再查看 `frontend/bindings` 实际生成的位置。本课程使用的路径为。

```javascript
import { GreetService, NoteService } from "../bindings/example.com/learn/first-wails/index.js";
```

本章故障副本使用了 `../bindings/wrong-module/index.js`，前端构建报告 `UNRESOLVED_IMPORT`。修正路径后，再执行同一次构建。

```powershell
Set-Location frontend
npm.cmd run build
Set-Location ..
```

错误与修复脚本保存在 `labs/binding-path`。新增服务方法时，也检查导出名称、实例注册和绑定任务，再重新生成绑定。

```powershell
wails3 generate bindings
```

生成规则和模块路径的对应关系以实际输出为准。[方法绑定说明](https://v3.wails.io/features/bindings/methods/)

## 7. 等待完成以后再更新成功状态

检查保存处理函数的先后顺序。

```javascript
await NoteService.Save(textToSave);
savedText = textToSave;
```

成功提示在调用完成后，根据当前编辑内容设置。配套完整工程保留了“保存期间继续输入”时的状态区分，失败则进入 `catch`。

## 8. 嵌入目录没有匹配文件

本章实测得到的错误为。

```text
main.go:10:12: pattern all:frontend/dist: no matching files found
```

嵌入指令需要匹配实际文件。在项目根目录准备一个只在缺失时写入的占位文件，再重新执行生成操作。

```powershell
New-Item -ItemType Directory -Path frontend\dist -Force | Out-Null
if (-not (Test-Path -LiteralPath frontend\dist\index.html)) {
    Set-Content -LiteralPath frontend\dist\index.html -Value '<!doctype html><title>Loading</title>' -Encoding utf8
}
wails3 generate bindings
wails3 dev
```

本机补齐占位文件后，Go 编译检查和绑定生成均通过。正常前端构建会生成实际产物，日常编辑回到 `frontend/index.html` 与 `frontend/src`。[Go embed 文档](https://pkg.go.dev/embed)

## 9. npm 与版本检查

若 PowerShell 报告 `npm.ps1` 执行策略问题，可以尝试同一套 Node 安装中的 `npm.cmd` 入口。制作环境验证了版本查询和安装命令。

```powershell
npm.cmd --version
Set-Location frontend
npm.cmd install
Set-Location ..
```

执行策略问题在视频中属于条件处理说明。依赖安装失败时，保留实际报错，再分别检查连接与代理情况，或 Node 版本与项目 Vite 要求。

```powershell
go version
node --version
wails3 doctor
```

本机使用 Node.js v24.19.0 与 npm 11.17.0。当前 Vite 包声明的 Node 要求为 `^20.19.0 || >=22.12.0`，这些记录来自本机命令输出与实际安装的 Vite 包，具体要求随项目依赖版本核对。

`wails3 doctor` 提供环境检查信息。[Wails 环境检查](https://v3.wails.io/guides/cli/)

## 10. 开发端口占用

本章通过实验进程占用本地端口 `65217`，复现 `Port 65217 is already in use`。结束实验占用后，同一个端口启动成功并返回 HTTP 200。

自行复现时，在前端目录选择可用的实验端口，先启动一份 Vite 服务，再在另一个终端用同一端口启动第二份。

```powershell
npm.cmd run dev -- --port 9247 --strictPort
```

第二份会报告端口占用。回到自己第一份服务的终端按 `Ctrl+C`，再重复第二份命令核对启动结果。

Wails 开发命令可以显式使用可用端口，本机原生窗口已用以下命令验证。

```powershell
wails3 dev -port 9246
```

保留 Go 返回的具体文件操作错误，核对页面底部的数据路径。重启读到旧内容时，检查本次是否保存成功，再核对重新读取的文件。
